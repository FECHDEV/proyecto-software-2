# Plan — HU-15 Subir el modelo 3D de un producto

Historia: `docs/historias/HU-15.md` · Issue #19 · Rama `feature/hu-15-modelo-3d`

El backend va primero: el formato `.glb` reconocido por su contenido, el modelo
en `Producto` con su subida, reemplazo y borrado, y el archivo servido como las
fotos. Después, los límites de subida, la demostración y, al final, el visor
(`<model-viewer>`) y la sección «Modelo 3D» del formulario del producto. Cada
tarea se prueba sola.

## Decisiones técnicas

- **Dependencias nuevas en el frontend** (se avisan antes de instalar):
  `@google/model-viewer@4.4.0` y `three@0.183.x`, la versión que pide él
  («Visor 3D y modelos»). El backend no suma nada.
- **El mismo almacén que las fotos.** `AlmacenImagenes` acepta también
  nombres `uuid.glb`, en la misma carpeta y el mismo volumen. Un almacén
  aparte repetiría el código de nombres seguros y de borrado sin aportar nada.
  No se renombra la clase, para no tocar lo que ya funciona.
- **`FormatoModelo.esGlb(byte[])`:** cabecera de 12 bytes con «glTF»,
  versión 2 y un largo declarado igual al del archivo, más el primer bloque de
  tipo JSON. Con eso se rechazan un `.gltf` de texto, la versión 1, un
  archivo vacío o cortado, y una foto renombrada.
- **El producto guarda `modelo` (el nombre del archivo) y `pesoModelo` (en
  bytes).** El peso sirve para mostrarlo y para el aviso de más de 1 MB sin
  leer el archivo.
- **Límites de subida:** `spring.servlet.multipart.max-file-size` pasa de 2
  a 3 MB y `max-request-size`, de 3 a 4 MB. Las fotos siguen en 2 MB, ahora
  controlados en el servicio (`AlmacenImagenes.MAXIMO_IMAGEN`), tanto en los
  productos como en las categorías. `ManejadorErrores` responde
  `MODELO_DEMASIADO_GRANDE` si la ruta termina en `/modelo` y
  `IMAGEN_DEMASIADO_GRANDE` si no. En `nginx.conf`, `client_max_body_size`
  queda en 5 MB, con margen sobre los 4 MB.
- **El frontend no manda un archivo de más de 3 MB:** lo rechaza con el mismo
  mensaje. Así un archivo de 30 MB no choca con el corte de nginx y no se
  sube en vano con datos móviles.
- **Visor en `shared/visor-3d/`.** Es un componente sin negocio que HU-16
  reutiliza. Carga `@google/model-viewer` con `import()` dentro de
  `afterNextRender`, en un fragmento aparte. La carga va detrás de un token
  (`CARGAR_VISOR_3D`) para que las pruebas sobre jsdom, sin WebGL, no lo
  importen.
- **Concurrencia y archivos:** como `agregarImagen`, se bloquea la fila del
  producto y `ArchivosAlTerminar` borra el archivo viejo solo si la
  transacción se confirma, y el nuevo si se revierte.

## Tarea 1 — El modelo en el producto · backend

**Archivos:** `service/FormatoModelo.java` (nuevo),
`service/AlmacenImagenes.java`, `entity/Producto.java`,
`service/ProductoService.java`, `dto/ProductoResponse.java`,
`dto/ProductoResumenResponse.java`, `dto/ModeloResponse.java` (nuevo),
`exception/ModeloInvalidoException.java` y
`exception/ModeloDemasiadoGrandeException.java` (nuevos, 400).

- `FormatoModelo`: `static boolean esGlb(byte[] contenido)`, con
  `TIPO_DE_CONTENIDO = "model/gltf-binary"` y `EXTENSION = "glb"`.
- `AlmacenImagenes`: `guardar(byte[], String extension)` (el de `FormatoImagen`
  la usa), el patrón de nombres acepta `glb`, y `MAXIMO_IMAGEN` (2 MB).
- `Producto`: `modelo` (`length = 64`) y `pesoModelo` (`Long`), con
  `cambiarModelo(String, long)` y `quitarModelo()`.
- `ProductoResponse` suma `ModeloResponse modelo` (`archivo`, `peso`, o
  `null`); `ProductoResumenResponse` suma `boolean conModelo`.
- `ProductoService`:

```java
static final long MAXIMO_MODELO = DataSize.ofMegabytes(3).toBytes();

// Como agregarImagen: con la fila bloqueada, dos reemplazos a la vez dejan un solo modelo; el anterior se borra
// solo si se confirma, y el nuevo si se revierte (decisiones.md → Visor 3D y modelos)
@Transactional
public ProductoResponse subirModelo(Long idProducto, byte[] contenido) {
	if (contenido.length > MAXIMO_MODELO) {
		throw new ModeloDemasiadoGrandeException();
	}
	if (!FormatoModelo.esGlb(contenido)) {
		throw new ModeloInvalidoException();
	}
	Producto producto = bloquear(idProducto);
	String anterior = producto.getModelo();
	String nuevo = almacen.guardar(contenido, FormatoModelo.EXTENSION);
	ArchivosAlTerminar.borrar(almacen, anterior, nuevo);
	producto.cambiarModelo(nuevo, contenido.length);
	return ProductoResponse.from(producto);
}

@Transactional
public ProductoResponse quitarModelo(Long idProducto) {
	Producto producto = bloquear(idProducto);
	if (producto.getModelo() != null) {
		ArchivosAlTerminar.borrar(almacen, producto.getModelo(), null);
		producto.quitarModelo();
	}
	return ProductoResponse.from(producto);
}

// Pública, como las imágenes: solo el modelo actual del producto
@Transactional(readOnly = true)
public Optional<byte[]> modelo(Long idProducto, String archivo) {
	return productoRepository.findById(idProducto).filter(producto -> archivo.equals(producto.getModelo()))
			.flatMap(producto -> almacen.leer(archivo));
}
```

- `agregarImagen` pasa a controlar los 2 MB (`ImagenDemasiadoGrandeException`),

### Revisiones

**Interfaz (subagente, `playwright-cli` con Edge, 12 capturas, API simulada en
el 4201 y un cubo `.glb` generado):** 6 hallazgos, 5 corregidos: el foco caía al
`body` si la subida fallaba (el campo de archivo va con `aria-disabled` y no
`disabled`); los avisos de éxito y de peso quedaban pegados; «REEMPLAZAR» en
mayúsculas junto a «Quitar» (el rótulo de `_formulario.scss` alcanzaba al label
que hace de botón: ahora `label:not(.boton)`, que también arregla «Subir foto»
y la imagen de las categorías); «Pesa 0,00 MB» en un modelo chico (debajo de
1 MB va en KB); «Cargando…» en una región que aparecía ya llena. Descartado: la
marca «3D» puede bajar sola de línea con un nombre largo (no desborda; es un
corte de línea normal).

**`/security-review` (subagente):** sin hallazgos (acceso, recorrido de rutas
en el GET, el almacén y la demostración, validación del `.glb`, tipo servido
con `nosniff`, tamaños, borrado y concurrencia, dependencias con `npm audit`
en 0).

**`/code-review` ronda 1 (9, 6 corregidos):** un fallo de la descarga del visor
quedaba recordado toda la sesión; subir fotos y el modelo a la vez podía
deshacer uno con la respuesta del otro (cada operación cambia solo lo suyo);
el modelo se servía sin caché (ahora `Cache-Control` de un año, `immutable`:
el nombre cambia con cada subida); los límites pasan a `FormatoModelo.MAXIMO` y
`FormatoImagen.MAXIMO`; un peso nulo daba 500; el mensaje del tamaño se arma por
su código (`mensajeDelCodigo`). Descartados: el código del error por la ruta en
`ManejadorErrores` (dos rutas de subida, probado); leer el `.glb` entero al
validar la demostración (una vez, al arrancar, hasta 3 MB); `label:not(.boton)`
cambia «Subir foto» y la imagen de categorías (es el arreglo buscado).

**`/code-review` ronda 2 (el tope; 10, 7 corregidos):** la prueba de la carrera
pasaba también con el código viejo (se rehízo); guardar los datos mientras
subía el modelo lo hacía desaparecer (`guardar()` conserva fotos y modelo); el
visor no volvía a intentar con otro modelo; un peso faltante se mostraba
«1 KB» y uno de casi 1 MB, «1.024 KB»; el selector de archivos se abría
mientras subía; el error del visor no se anunciaba. Descartado: una ruta con
barra final en `ManejadorErrores` (no es una ruta de la API y la pantalla usa
siempre la misma).

### Distinto de lo planeado

- La tarjeta «Modelo 3D» es un componente aparte
  (`features/producto/modelo-de-producto`): `producto.page.scss` ya estaba en
  5,96 de los 6 kB del presupuesto. Usa el diálogo de la pantalla.
- `CARGAR_VISOR_3D` devuelve si hay WebGL (true o false), y
  `cargadorDeVisor` recuerda la respuesta pero no un fallo.
- Los límites quedaron en `FormatoModelo.MAXIMO` y `FormatoImagen.MAXIMO`, no
  en `ProductoService` y `AlmacenImagenes`.
- Una ruta con `../` la rechaza el firewall de Spring con 400 antes del
  controlador; la historia dice «400 o 404».
- El peso se muestra en KB debajo de 1 MB; el aviso, con dos decimales
  («2,40 MB»).
- Los tres casos inválidos de la demostración van en una prueba,
  `unModeloInvalidoNoCargaNada`.
- El GET del modelo lleva `Cache-Control` inmutable de un año.
