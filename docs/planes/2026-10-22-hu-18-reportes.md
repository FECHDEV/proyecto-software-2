# Plan — HU-18 Reportes de ventas e ingresos

Historia: `docs/historias/HU-18.md` · Issue #22 · Rama `feature/hu-18-reportes`

Primero los dos datos que faltan (el costo del producto y el tipo de cliente),
después la API de reportes en `/api/reportes` (un resumen con todo lo que no
se pagina y cuatro listas paginadas) y al final la pantalla `/reportes` con
cinco secciones. Cada tarea se prueba sola.

## Decisiones técnicas

- **Agregar en la base, ordenar y paginar en Java.** Las consultas JPQL traen
  sumas agrupadas (por pedido, por producto) del período; las secciones, la
  comparación, «menos vendidos» (que incluye los productos sin ventas) y las
  páginas se arman en `ReportesService`. **Motivo:** una ferretería de un
  local tiene cientos o pocos miles de productos y de pedidos por año; en Java
  el mismo código vale en H2 y en MySQL (día de la semana, hora y fecha sin
  funciones de cada base) y no hace falta una consulta de conteo por cada
  lista agrupada.
- **Dos consultas con subconsulta** (sin venderse y clientes inactivos), porque
  filtran por la última venta y se paginan en la base. Si HQL no las acepta en
  H2, se pasan a Java como las demás.
- **Lectura con `@Transactional(readOnly = true)`,** sin bloqueos: un reporte
  no cambia nada y no necesita la foto exacta de un instante.
- **Las enumeraciones nuevas van como `varchar`** (`@JdbcTypeCode(SqlTypes.VARCHAR)`),
  como `pedido.estado` desde HU-17: un `enum` de MySQL no admite valores
  nuevos sin migración. Las columnas nuevas en tablas con filas llevan
  `@ColumnDefault`, como `correo_verificado`.
- **Los parámetros del período llegan como texto** y los lee `Periodo.de(...)`:
  una fecha que no se entiende, «desde» después de «hasta», «hasta» futura o
  más de 366 días es 400 `PERIODO_INVALIDO`. La pantalla corrige la dirección
  antes de llamar (RF-3), así que el 400 solo lo ve quien llama a mano.

**Lo delicado: el período y el dinero.** Las fechas se cortan con «menor que
el día siguiente» (un pago a las 23:59:59,9 entra) y en la zona del `Clock`
(La Paz). El margen solo suma las líneas con costo:

```java
// Periodo: lo que llega por la dirección. Sin fechas, del 1 del mes a hoy (RF-2)
public record Periodo(LocalDate desde, LocalDate hasta) {

	static final int MAXIMO_DIAS = 366;
	static final int MAXIMO_DIAS_POR_DIA = 62;

	public static Periodo de(String desde, String hasta, LocalDate hoy) {
		if (desde == null && hasta == null) {
			return new Periodo(hoy.withDayOfMonth(1), hoy);
		}
		LocalDate inicio = leer(desde);
		LocalDate fin = leer(hasta);
		if (fin.isAfter(hoy) || inicio.isAfter(fin) || ChronoUnit.DAYS.between(inicio, fin) + 1 > MAXIMO_DIAS) {
			throw new PeriodoInvalidoException();
		}
		return new Periodo(inicio, fin);
	}

	private static LocalDate leer(String fecha) {
		try {
			return LocalDate.parse(Objects.requireNonNull(fecha));
		} catch (DateTimeParseException | NullPointerException e) {
			throw new PeriodoInvalidoException();
		}
	}

	public long dias() {
		return ChronoUnit.DAYS.between(desde, hasta) + 1;
	}

	// Los días inmediatamente antes, del mismo largo (RF-7)
	public Periodo anterior() {
		return new Periodo(desde.minusDays(dias()), desde.minusDays(1));
	}

	public LocalDateTime inicio() {
		return desde.atStartOfDay();
	}

	public LocalDateTime fin() {
		return hasta.plusDays(1).atStartOfDay(); // excluido
	}

	public boolean porMes() {
		return dias() > MAXIMO_DIAS_POR_DIA;
	}
}
```

Los totales salen de esas filas: `ingresos` = suma de `total` de los
pedidos; `margen` = suma de `margen`, redondeado a 2 con `HALF_UP`;
`margenPorcentaje` = margen ÷ (importe − sinCosto) × 100, con un decimal,
nulo si el divisor es 0; `promedio` = ingresos ÷ pedidos, nulo con 0
pedidos. La proporción de perdidos es vendidos ÷ (confirmados − los que
siguen pendientes de pago).

## Tarea 5 — La pantalla `/reportes` · frontend

**Archivos:** `core/modelos/reportes.ts` y `core/api/reportes.service.ts`
(nuevos); `features/reportes/` (nueva: la página con el período, el filtro
por tipo y las pestañas) con una pieza por sección (`reportes-resumen`,
`reportes-productos`, `reportes-sin-venta`, `reportes-clientes`,
`reportes-perdidos`), para no pasar los 6 kB de estilos por componente;
`app.routes.ts` (`/reportes` con el guard de rol para `CONTADOR` y
`ADMINISTRADOR`), `app.component.ts` (`MODULOS`) y el panel.

- **La dirección manda,** como en `/pedidos`: `seccion` (`resumen` de
  entrada, `productos`, `sin-venta`, `clientes`, `perdidos`), `desde`,
  `hasta`, `tipo`, `orden`, `dias` y `pagina`; lo de entrada no se escribe.
  `leerConsultaDeReportes(ParamMap, hoy)` corrige lo que no sirve (RF-3): sin
  fechas o ilegibles, «Este mes»; «hasta» futura, hoy; «desde» después de
  «hasta», se cambian; más de 366 días, «desde» se acerca a «hasta»; y avisa
  «Se ajustó el período» si cambió algo que se escribió. **Hoy es el de
  Bolivia** (`America/La_Paz`), no el del navegador: con otra zona, un
  «hasta» de mañana sería un 400 del servidor.
- **Período:** los cuatro atajos como botones (el activo marcado) y dos
  `input type="date"` con `max` en hoy. **Tipo:** selector «Todos los
  clientes» y los cuatro tipos.
- **Resumen:** cinco cifras con la del período anterior y la diferencia
  («▲ 12 %», «▼ 3 %», «sin ventas antes»), margen negativo en el tono de
  error; tabla por día (o mes) con una barra de CSS proporcional; tablas por
  día de la semana y por hora; por categoría y por tipo.
- **Productos:** «Más vendidos» / «Menos vendidos» y la tabla paginada.
  **Sin venderse:** «Más de 30 / 60 / 90 días» y la tabla con el inmovilizado
  (marcado «a precio» si no hay costo). **Clientes:** inactivos con correo
  (`mailto:`) y teléfono (`tel:`). **Perdidos:** las cifras y la tabla.
- Lecturas con `httpResource`; cada sección pide solo lo suyo. Mientras
  carga, error con «Reintentar» y sin datos (RF-22). Montos con `precio()`,
  fechas con `fechaCorta`.
- Antes de las tablas con barras, leer la skill `dataviz` (colores y
  accesibilidad de la barra) y `DESIGN.md`.
